# Краткая справка по скриптам

По исходному коду на 05.09.2026. Описаны все 15 Ruby-файлов проекта: 8 запускаемых скриптов, 3 библиотеки и 4 набора тестов. Временные служебные файлы `.codex_tmp/` не включены.

## Запускаемые скрипты

### `DB/create_tables.rb`
- **Вход:** аргументов нет; путь к базе фиксирован — `DB/operations.db`.
- **Что делает:** создаёт SQLite-базу и 8 таблиц для провайдеров, очереди, истории, решений, попыток, допустимости, причин пропуска и эталонов. Существующие таблицы и данные сохраняет.
- **Выход:** файл базы с таблицами; в консоли — `OK` и список таблиц. Исходные данные не загружает.

### `bin/import_data.rb`
- **Вход:** существующая база со схемой `DB/create_tables.rb`; каталог `data/` с `providers.json`, `operations_history.csv`, `reference_decisions.json`, `operations_queue.json` (при отсутствии — `operations_queue_10.json`). Параметры: `--database`, `--data-dir`, `--include-sample`.
- **Что делает:** одной транзакцией добавляет отсутствующие исходные записи, эталонную допустимость и причины пропуска; существующие записи не обновляет. С `--include-sample` также читает `sample_routing_decisions.json` и загружает решения и попытки.
- **Выход:** заполненная база; в консоли — число добавленных и пропущенных записей по таблицам. При ошибке импорт откатывается.

### `bin/import_sources.rb`
- **Вход:** совместимая база с таблицей `analytics_metadata`; по умолчанию файлы `data/providers.json`, `data/operations_history.csv`, `data/operations_queue_10.json`, `data/reference_decisions.json`. Пути задаются через `--database`, `--providers`, `--history`, `--queue`, `--references`.
- **Что делает:** добавляет или обновляет метаданные, провайдеров, историю, очередь и детерминированные эталоны. Удаляет из очереди операции, перенесённые в историю, и не возвращает обработанные заявки в очередь.
- **Выход:** обновлённая база; в консоли — количество обработанных записей. Импорт выполняется транзакционно; таблицы не создаются.

### `bin/log_operations.rb`
- **Вход:** обязательные `--operations PATH` (JSON заявок в формате очереди) и `--decisions PATH` (JSON готовых решений с `operation_id`, `selected_provider`, `attempts`, результатом и задержкой при наличии); необязательный `--database`. Наборы `operation_id` должны совпадать и не содержать повторов; провайдеры должны быть в базе.
- **Что делает:** транзакционно сохраняет историю и решения, заменяет попытки, признаки допустимости и причины пропуска; удаляет обработанные заявки из очереди. Сам провайдера не выбирает.
- **Выход:** обновлённая база; в консоли — число записанных операций. Требуется совместимая схема с `analytics_metadata` и связями, допускающими удаление заявки из очереди.

### `bin/update_provider_minute_stats.rb`
- **Вход:** существующая база с `providers` и `operations_history`; параметры `--database`, `--at ISO8601` (время с часовым поясом, по умолчанию сейчас), `--dry-run`.
- **Что делает:** по времени создания операций рассчитывает показатели текущей и предыдущей минуты, последнего часа, 24 часов и текущего дня UTC: количество, суммы, статусы, задержки, доли, отклонения от целей, разбивки по банкам и суммам. Минутное окно — `(момент расчёта − 60 секунд, момент расчёта]`.
- **Выход:** JSON в консоли. Без `--dry-run` также обновляет в `providers` поля `in_progress_count`, `in_progress_amount`, `conversion_24h`, `avg_latency_sec`, добавляет недостающие 12 колонок минутных показателей и 2 колонки времени/длины окна. `requests_last_minute` обновляет только при наличии колонки. `in_progress_*` здесь учитывают все статусы за минуту. С `--dry-run` база не меняется.

### `bin/analyze.rb`
- **Вход:** SQLite-база с совместимой аналитической схемой, включая `analytics_metadata`; параметры `--database`, `--output`, `--stdout`.
- **Что делает:** читает данные и рассчитывает распределение операций и сумм по провайдерам и дням, статусы, конверсию, задержки, загрузку лимитов, очередь, причины пропуска, рекомендации и проверки качества данных.
- **Выход:** `reports/routing_report.json` либо файл из `--output`; с `--stdout` — JSON в консоли без записи файла. База открывается только для чтения.

### `bin/analyze_db.rb`
- **Вход:** SQLite-база с точной схемой из `DB/create_tables.rb`; параметры `--database`, `--output`, `--stdout`.
- **Что делает:** проверяет таблицы, колонки и внешние ключи, формирует общую аналитику; объединяет причины пропуска из отдельных записей и попыток без повторного подсчёта одинаковых сочетаний операции, провайдера и причины.
- **Выход:** `reports/routing_report_db.json` либо файл из `--output`; с `--stdout` — JSON в консоли. Базу не меняет; несовместимую схему отклоняет.

### `scripts/validate_10.rb`
- **Вход:** путь к JSON с решениями первым аргументом; дополнительно читает `data/operations_queue_10.json`, `data/providers.json`, `data/reference_decisions.json`.
- **Что делает:** проверяет поля решений и попыток, покрытие 10 заявок, детерминированные эталоны, допустимость выбранных провайдеров по снимку и ожидаемые пропуски. Минутный лимит и последовательное изменение состояния между заявками не проверяет.
- **Выход:** результаты проверок, ошибки и предупреждения в консоли; код завершения `0` при отсутствии ошибок, иначе `1`. Входные файлы не меняет.

## Библиотеки

Подключаются через `require_relative`; сами по себе отчёты не печатают и CLI не предоставляют.

### `lib/routing_analytics.rb`
- **Вход:** в зависимости от класса — пути JSON/CSV или SQLite-базы, структуры провайдеров, истории, очереди и готовых решений; для сохранения отчёта — путь и Ruby Hash.
- **Что делает:** загружает данные (`Loader`), читает базу (`DatabaseSource`), импортирует и записывает результаты (`DatabaseWriter`), рассчитывает аналитику без двойного подсчёта операций (`Analyzer`), сохраняет JSON (`ReportWriter`).
- **Выход:** структуры данных и отчёт как Ruby Hash; методы записи изменяют базу или создают JSON-файл. Методы импорта возвращают счётчики, журналирования — количество операций, сохранения отчёта — путь к файлу.

### `lib/canonical_database_analytics.rb`
- **Вход:** путь к SQLite-базе с точной исходной схемой из 8 таблиц; для отчёта можно передать время формирования `generated_at`.
- **Что делает:** проверяет схему, адаптирует записи к общему `Analyzer`, собирает сведения о целостности и связанных записях, объединяет причины пропуска.
- **Выход:** входные структуры для аналитики и готовый отчёт как Ruby Hash. Базу читает без изменений; файл отчёта самостоятельно не сохраняет.

### `lib/provider_minute_metrics.rb`
- **Вход:** массивы операций за уже выбранный период (`amount`, `status`, `latency_sec`, `bank`), общие итоги и параметры провайдера с целевыми долями и лимитами.
- **Что делает:** вычисляет суммы, количество, проценты статусов, среднюю/медианную/p95 задержку, доли провайдеров, изменения, отклонения от целей, использование лимитов и разбивки по банкам/диапазонам сумм.
- **Выход:** числа, массивы и Ruby Hash с показателями; неопределимые проценты и задержки возвращает как `nil`. Файлы и базу не читает и не изменяет.

## Тесты

Все наборы используют Minitest. Общий выход — статистика тестов, проверок, ошибок и провалов в консоли; код завершения `0` при успехе, ненулевой при неуспехе. Тестовые записи выполняются во временные копии базы.

### `test/import_data_test.rb`
- **Вход:** `DB/operations.db` как шаблон исходной схемы и файлы `data/`.
- **Что делает:** проверяет импорт, сохранение схемы, существующих значений и ID, загрузку примеров по флагу, повторный импорт, откат при ошибке и запуск из другого каталога.
- **Выход:** результат Minitest; временная база удаляется, неизменность исходной проверяется по хешу.

### `test/provider_minute_stats_test.rb`
- **Вход:** `DB/operations.db` как шаблон с провайдерами и операции, создаваемые тестами во временной базе.
- **Что делает:** проверяет границы периодов и часовые пояса, все статусы, показатели и разбивки, повторный расчёт, некорректные данные, откат записи, CLI и режим `--dry-run`.
- **Выход:** результат Minitest; временная база удаляется, неизменность исходной проверяется по хешу.

### `test/canonical_database_analytics_test.rb`
- **Вход:** `DB/operations.db` с исходной схемой и ожидаемыми тестом данными.
- **Что делает:** проверяет показатели отчёта, корректность JSON, отклонение несовместимой схемы и сохранность исходной базы.
- **Выход:** результат Minitest; временные файлы проверок удаляются.

### `test/routing_analytics_test.rb`
- **Вход:** файлы `data/` и `DB/operations.db` как шаблон совместимой схемы с `analytics_metadata`.
- **Что делает:** проверяет импорт и аналитику, замену состояния при повторной записи решения, чтение без изменения базы, сохранение JSON и запрет записи в защищённые каталоги.
- **Выход:** результат Minitest; тестовые базы и отчёты во временных каталогах удаляются.

## Особенности совместимости

- Во всех командах `bin/` база по умолчанию — `DB/operations.db`.
- `DB/create_tables.rb` создаёт 8 таблиц, но не `analytics_metadata`. Для `import_sources.rb`, `log_operations.rb`, `analyze.rb` и соответствующего теста нужна отдельно подготовленная совместимая схема.
- Запись через `update_provider_minute_stats.rb` добавляет колонки, после чего строгая проверка в `analyze_db.rb` отклонит такую базу. `--dry-run` схему сохраняет.
- Причины пропуска, загруженные `import_data.rb` из эталонов, попадут в отчёт `analyze_db.rb` вместе с фактическими попытками; это могут быть ожидаемые, а не наблюдавшиеся пропуски.
