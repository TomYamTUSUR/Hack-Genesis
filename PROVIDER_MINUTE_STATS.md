# Статистика провайдеров

```powershell
ruby bin/update_provider_minute_stats.rb
ruby bin/update_provider_minute_stats.rb --dry-run
ruby bin/update_provider_minute_stats.rb --at 2026-07-29T12:41:18+03:00 --dry-run
```

`--database PATH` выбирает существующую SQLite-базу; по умолчанию используется
`DB/operations.db`, независимо от рабочего каталога. `--at` задаёт конец периода
с явным часовым поясом, по умолчанию используется текущее время.

Скрипт не создаёт и не изменяет таблицы, колонки, индексы или ограничения.
Обычный запуск обновляет записи провайдеров одной транзакцией. `--dry-run`
открывает базу только для чтения. Результат обоих режимов — JSON в stdout;
ошибка выводится в stderr и возвращает ненулевой код, запись откатывается.

## Запись в существующие поля

| Поле providers | Значение |
|---|---|
| `in_progress_count` | Число заявок, созданных за последнюю минуту, всех статусов |
| `in_progress_amount` | Их суммарная сумма |
| `conversion_24h` | Число `approved` / число всех заявок за последние 24 часа; коэффициент 0…1 |
| `avg_latency_sec` | Среднее известных `latency_sec` за последнюю минуту, все статусы, округление до целых секунд |
| `requests_last_minute` | Число заявок за минуту; обновляется **только если колонка уже существует** |

Пустая выборка даёт нулевые количество и сумму, но `NULL` для конверсии и среднего
времени. Повторный запуск заменяет значения актуальными, не прибавляет их.
Цели, лимиты, `daily_approved_amount` и остальные поля не изменяются.

## JSON

`providers` содержит рассчитанные поля и следующие группы:

- `periods`: `minute`, `previous_minute`, `last_hour`, `last_24h`,
  `today_created_operations`. Каждая группа содержит количество, сумму, средний,
  минимальный и максимальный чек; количество, сумму и проценты каждого статуса;
  успешность по количеству и сумме; доли провайдера по количеству, сумме и успешной
  сумме; успешность среди завершённых операций; среднее, медиану и p95 задержки
  отдельно для всех известных значений и для успешных операций.
- `minute_change`: разница количества и суммы с предыдущей минутой, в абсолютных
  значениях и процентах.
- `targets`: отклонения фактических долей от целей в процентных пунктах,
  использование и остаток минутного лимита; использование и остаток дневного
  лимита и выполнение дневных обязательств по **имеющемуся снимку провайдера**.
- `minute_breakdown`: те же показатели по банкам и диапазонам суммы за минуту.
  Доли этих групп считаются внутри текущего провайдера. Диапазоны не пересекаются:
  `[0,1000)`, `[1000,10000)`, `[10000,50000)`, `[50000,100000)`, `[100000,+∞)`.

`totals` содержит сводные метрики всех провайдеров для каждого периода. `windows`
явно задаёт границы. `persistence` перечисляет поля записи и режим запуска.
`definitions` содержит определения показателей и ограничения интерпретации.

## Формулы и периоды

- Доля количества = `100 × count_provider / count_all`.
- Доля суммы = `100 × amount_provider / amount_all`.
- Доля успешной суммы = `100 × approved_amount_provider / approved_amount_all`.
- Успешность = `100 × approved_count / count_provider`; аналогично для отказов
  `rejected` и истечений `expired`.
- Успешность по сумме = `100 × approved_amount_provider / amount_provider`.
- Успешность среди завершённых = `100 × approved / (approved + rejected + expired)`.
  Другие статусы не считаются завершёнными.
- Изменение к предыдущей минуте = `100 × (current - previous) / previous`.
- Отклонение от цели = `actual_pct - target_pct`, в процентных пунктах.
- p95 определяется методом ближайшего ранга: элемент `ceil(0.95 × n)`
  отсортированного списка. Для медианы чётного списка берётся среднее двух средних.

Все проценты в JSON — числа от 0 до 100, кроме изменений, отклонений и загрузки
лимитов, которые могут выходить за эти границы. Дробные результаты округляются
до четырёх знаков; сохраняемый `conversion_24h` остаётся коэффициентом 0…1.
Нулевой или отсутствующий знаменатель даёт `null`, не 0%. Нулевой/отсутствующий
лимит также даёт `null`. Отрицательный остаток лимита означает превышение.
Всегда доступны количества наблюдений для оценки устойчивости процентов.

Скользящие окна: `(конец - длительность, конец]`; предыдущая минута:
`(конец - 120 секунд, конец - 60 секунд]`. Календарный день считается по UTC,
`[00:00 UTC, конец]`. Метки с UTC-смещением нормализуются SQLite; метки без
смещения SQLite трактует как UTC. Пропуски задержки не превращаются в нули.

## Ограничения исходных данных

Источником служит `operations_history.created_at`. Одна запись означает одну
зарегистрированную заявку провайдеру: фактических HTTP-обращений и повторных
отправок она не отражает. `--at` использует текущие сохранённые статусы, а не
восстанавливает состояние заявки в прошлом.

По согласованному правилу поля `in_progress_count` и `in_progress_amount`
отражают минутный поток, не одновременно обрабатываемые заявки. Поэтому скрипт
не рассчитывает их загрузку относительно лимитов одновременной обработки.
Старые потребители этих полей могут по-прежнему интерпретировать их как загрузку.

Время завершения выплат отсутствует. Дневная сумма `approved` в отчёте относится
к заявкам, **созданным** за день, поэтому не заменяет `daily_approved_amount`.
Свежесть снимка провайдера и полноту истории база не удостоверяет. Минутные
статусы недавно созданных заявок могут ещё измениться.

Прочие метрики остаются в JSON: в текущей схеме нет соответствующих полей.
Фактические доли не записываются в `traffic_percentage` и `volume_share_pct`,
поскольку это настройки целей. Для полного журнала повторных отправок текущих
данных недостаточно.
